# Requisitos do Sistema — AcolheSP

## 1. Requisitos Funcionais

Os requisitos funcionais descrevem as funcionalidades que o sistema deverá oferecer aos usuários.

### RF01 — Cadastro de usuário
O sistema deve permitir que pessoas interessadas em realizar doações ou trabalho voluntário realizem seu cadastro na plataforma.

### RF02 — Cadastro de instituição
O sistema deve permitir que responsáveis por abrigos e instituições de apoio realizem o cadastro da instituição, informando nome, endereço, contato, descrição e serviços oferecidos.

### RF03 — Validação de instituição
O sistema deve permitir a validação das instituições cadastradas antes que suas informações sejam disponibilizadas aos demais usuários.

### RF04 — Localização das instituições
O sistema deve permitir que o usuário utilize sua localização atual ou informe manualmente uma região ou endereço para encontrar instituições de apoio próximas.

### RF05 — Visualização das instituições
O sistema deve apresentar as instituições encontradas em formato de lista e em um mapa geográfico.

### RF06 — Consulta de informações
O sistema deve permitir que o usuário consulte informações de uma instituição, incluindo localização, formas de contato, serviços oferecidos, necessidades e oportunidades de voluntariado.

### RF07 — Pesquisa e filtragem
O sistema deve permitir que o usuário pesquise e filtre instituições de acordo com critérios como localização, distância, serviços oferecidos e necessidades disponíveis.

### RF08 — Recomendação por proximidade
O sistema deve recomendar instituições de apoio considerando a proximidade entre a localização utilizada pelo usuário e a localização das instituições cadastradas.

### RF09 — Cadastro de necessidades
O sistema deve permitir que as instituições cadastrem produtos ou recursos necessários, informando sua descrição e quantidade.

### RF10 — Consulta de necessidades
O sistema deve permitir que os usuários consultem as necessidades cadastradas pelas instituições.

### RF11 — Manifestação de interesse em doação
O sistema deve permitir que o usuário manifeste interesse em realizar uma doação para atender uma necessidade cadastrada por uma instituição.

### RF12 — Atualização de necessidades
O sistema deve permitir que a instituição atualize as informações de suas necessidades.

### RF13 — Encerramento de necessidade
O sistema deve permitir que a instituição marque uma necessidade como atendida, fazendo com que ela deixe de ser apresentada como pendente.

### RF14 — Cadastro de oportunidades de voluntariado
O sistema deve permitir que as instituições cadastrem oportunidades de voluntariado, informando a atividade, descrição das tarefas, datas, horários e quantidade de voluntários necessários.

### RF15 — Consulta de oportunidades de voluntariado
O sistema deve permitir que os usuários consultem as oportunidades de voluntariado disponíveis nas instituições.

### RF16 — Manifestação de interesse em voluntariado
O sistema deve permitir que o usuário manifeste interesse em participar de uma oportunidade de voluntariado.

### RF17 — Consulta de interessados
O sistema deve permitir que a instituição consulte os usuários que manifestaram interesse em realizar doações ou participar de oportunidades de voluntariado.

### RF18 — Atualização dos dados da instituição
O sistema deve permitir que a instituição atualize seus dados cadastrais e suas informações disponibilizadas na plataforma.

## 2. Requisitos Não Funcionais

Os requisitos não funcionais definem características de qualidade, restrições e condições que o sistema deverá atender.

### RNF01 — Usabilidade
O sistema deve possuir uma interface simples e intuitiva, permitindo que pessoas com diferentes níveis de experiência tecnológica utilizem suas principais funcionalidades.

### RNF02 — Acessibilidade
O sistema deve utilizar textos claros, elementos visuais compreensíveis e uma organização que facilite a utilização por pessoas com diferentes necessidades.

### RNF03 — Facilidade de navegação
O sistema deve permitir que as principais funcionalidades sejam realizadas utilizando poucos passos, evitando fluxos desnecessariamente complexos.

### RNF04 — Responsividade
O sistema deve adaptar sua interface para diferentes tamanhos de tela, incluindo computadores, tablets e smartphones.

### RNF05 — Desempenho
O sistema deve apresentar as informações das instituições, necessidades, oportunidades de voluntariado e localização em tempo adequado para a utilização da plataforma.

### RNF06 — Segurança
O sistema deve proteger os dados armazenados contra acessos e alterações não autorizadas.

### RNF07 — Privacidade
O sistema deve coletar e disponibilizar somente os dados pessoais necessários para o funcionamento das funcionalidades da plataforma.

### RNF08 — Controle de acesso
O sistema deve restringir as funcionalidades administrativas às instituições e usuários devidamente autorizados.

### RNF09 — Integridade dos dados
O sistema deve garantir a consistência das informações referentes às instituições, necessidades, oportunidades de voluntariado e usuários cadastrados.

### RNF10 — Confiabilidade
O sistema deve disponibilizar informações consistentes e atualizadas sobre as instituições, suas necessidades e oportunidades de voluntariado.

### RNF11 — Compatibilidade
O sistema deve funcionar nos principais navegadores utilizados em computadores e dispositivos móveis.

### RNF12 — Manutenibilidade
O sistema deve possuir uma estrutura que facilite a manutenção, correção de erros e implementação de novas funcionalidades.

### RNF13 — Escalabilidade
O sistema deve permitir o crescimento da quantidade de usuários, instituições, necessidades e oportunidades cadastradas sem comprometer suas funcionalidades principais.

### RNF14 — Precisão da localização
O sistema deve utilizar informações de localização com precisão suficiente para calcular a proximidade entre o usuário e as instituições de apoio.
